\chapter{Test programs}\label{chap:tests}

\section*{At a glance}
\begin{itemize}
\item \lead{Goal} Discharge every hypothesis of \code{erase\_correct\_statement} on six concrete programs, apply the final theorem to each, and show that the rules of the source semantics that a program can reach are instantiated.
\item \lead{Main results} NV-0 (a polymorphic identity), NV-1 (\code{B.neg} on a two-constructor type), NV-2 (a \code{casesOn} with $\eta$-expanded constructors), NV-3 (\code{Nat.rec} and \code{Nat.casesOn} on literals), NV-4 (a quotient lift and \code{casesOn} on proofs), NV-5 (a projection, a \code{let} and an erased function applied). Section~\ref{sec:tests-table} tabulates what discharges each hypothesis, Section~\ref{sec:tests-rules} the rules.
\item \lead{Status} \stProved{} every hypothesis on all six programs, \code{erase\_correct} on each (\code{Test.NV}$k$\code{.final}), \code{erase\_correct\_firstorder} on NV-1 to NV-5, and the shape check \code{declOf?} on blocks outside their own \code{all}, unsafe and nested. The instances of NV-1 to NV-5 take the compiled facts as hypotheses.
\item \lead{Nodes} \bpnodes{chap:tests}
\item \lead{Lean files} \leanfiles{proof/EraseProof/Test/}{NV0Data, NV0Premises, NV0Final, NV1Data, NV1Run, NV1Premises, NV1Final, NV2Data, NV2Premises, NV2Final, NV3Data, NV3Premises, NV3Final, NV4Data, NV4Premises, NV4Final, NV5Data, NV5Premises, NV5Final, NVKit, RecIH, Run, DeclOf}.
\end{itemize}

\section{The programs and their hypotheses}\label{sec:tests-table}

Each program has a data node (its declarations as Lean generates them, checked against the elaborator by \code{NVEmit}), a node for its hypotheses and a node for the final theorem. The hypotheses are theorems named \code{Test.NV}$k$\code{.<hypothesis>}; the instance theorem \code{Test.NV}$k$\code{.final} applies \code{erase\_correct} to them.

\begin{itemize}
\item \lead{Why \code{constAtom}} it needs an unmarked constant without $\delta$, which the oracle never leaves unmarked: a theorem head is answered \code{true} first, a constant whose declared type is an arity has an arity type, and one whose type is an evident proposition has a $\Pi$ ending in a sort that \code{alwaysZero} reads as zero. Every atom spine is marked \code{erase} and evaluates by \code{frozen}, at every level instantiation.
\item \lead{Why \code{appCong}} its premise holds only of atom spines, so every derivation of it contains one of \code{constAtom}.
\item \lead{Why \code{projFrozen}} it needs an unmarked projection out of a \code{Prop} structure. con-leche types such a projection only if the field is a proposition at that instantiation; the oracle then sees the sort zero and marks the projection \code{erase}. No rule builds a bare projection, and a definition that projects at a level parameter is rejected by the fold.
\item \lead{Consequence} the three rules and their cases in the simulation and in the meaning of evaluation are dead on accepted programs. They are harmless: the statements quantify over \code{SrcEval}.
\end{itemize}

\section*{Caveats}
\begin{itemize}
\item In NV-1 to NV-5, \code{hfold} (con-leche's fold returns the stated environment) is checked by a compiled \code{\#guard} and enters the instance as a hypothesis (DV-40); NV-3 and NV-4 do the same for \code{hg}. The compiled code includes con-leche's \code{implemented\_by} and \code{extern} code.
\item The programs have no mutual inductive, no \code{brecOn} definition, no \code{@[extern]} with a companion and no theorem in the closure.
\item The corollary is instantiated on NV-1 to NV-5; the value of NV-0 is a function.
\end{itemize}
