\section{What is verified}\label{sec:intro-what}

\begin{itemize}
\item \lead{The eraser} \code{lean-to-lambdabox} is the Lean~4 frontend of Peregrine. The command
  \code{\#erase t config c to "f.ast" mli "f.mli"} elaborates the term \code{t}, erases it and the
  constants it depends on to a $\lambda_\Box$ program, and writes three files:
  \begin{itemize}
  \item \code{f.ast}: the program as an S-expression, which Peregrine (\code{peregrine-tool})
        reads and compiles;
  \item \code{f.ast.inlinings}: the constants Peregrine should inline;
  \item \code{f.mli}: an OCaml signature for the compiled program.
  \end{itemize}
  Section~\ref{sec:trust-shipping} describes the code.
\item \lead{The object} \hl{the shipping eraser itself}, not an eraser written for the proof: the
  theorem speaks about the code that \code{\#erase} runs.
\item \lead{The theorem} \code{erase\_correct} (Chapter~\ref{chap:final}): if \code{\#erase}
  returns a program for an in-scope term and the term evaluates, the program's main term evaluates
  in $\lambda_\Box$ to an erasure of the term's value. It mirrors MetaRocq's \code{erase\_correct}.
\item \lead{The kernel theory} Metalean (Section~\ref{sec:intro-metalean}): typing, definitional
  equality and well-formed environments of Lean's kernel, with inductive types, recursors and
  quotients.
\item \lead{The scope} closed, typed Lean programs that Metalean can express and that the
  eraser's fragment test admits, inductive types and \code{casesOn} included
  (Chapter~\ref{chap:scope}).
\item \lead{The references} the verification follows these as closely as the differences between
  Lean and Rocq allow; every divergence from the first two is an entry of
  \code{doc/DIVERGENCES.md}.
\end{itemize}

\section{Metalean}\label{sec:intro-metalean}

\begin{itemize}
\item \lead{What it is} a formalization of Lean's type theory in Lean
  (\code{github.com/intgrah/metalean}), pinned at commit \code{9407ba44}
  (Section~\ref{sec:intro-pins}).
\item \lead{What the proof uses} its syntax (\leandecl{Metalean.Expr}, \leandecl{Metalean.Env}),
  its typing judgment \leandecl{Metalean.Defeq} with type equality \leandecl{Metalean.TypeEq}, its
  well-formed environments \leandecl{Metalean.EnvWF}, its weak-head reduction
  \leandecl{Metalean.WHRed} with subject reduction \leandecl{Metalean.WHRed.defeq}, unique typing
  \leandecl{Metalean.Defeq.uniqTy}, and its domain model
  (\leandecl{Metalean.TypeEq.rawInterpret_eq}).
\item \lead{What it covers} $\lambda$, $\Pi$, sorts over a quotient of universe levels,
  \code{let}, constants, mutual and indexed inductive types, recursors with $\iota$- and K-like
  reduction, primitive quotients, proof irrelevance, $\eta$ and structure $\eta$.
\item \lead{What it declines} nested inductives, \code{unsafe} and \code{partial} declarations,
  \code{@[implemented\_by]}, string literals; theorems are opaque.
\item \lead{Trust} no \code{sorry}; one axiom, \code{Cardinal.exists\_inaccessibles}, which only
  its set-theoretic model uses and which no module of this repository imports
  (Section~\ref{sec:trust-metalean}).
\item \lead{Used as a library} Metalean's sources are never edited; lemmas about its theory that
  it does not state live in \leanfile{proof/}.
\end{itemize}

\section{Kinds, statuses and dependency graphs}\label{sec:intro-kinds}

\begin{itemize}
\item \lead{Kind} \code{blueprint/scripts/kinds.py} derives the kind of every node from its Lean
  declarations, its environment, and the \code{\textbackslash uses} of the final theorem and the
  milestones. The audit checks the derivation, and checks the \code{\textbackslash uses} of a
  formalized final theorem or milestone against its Lean proof. The kind sets the badge after the
  node's heading, the bar beside the node in the web version, and the node's shape and fill in the
  dependency graphs.
\item \lead{Colour families} Blue for the proof library \code{EraseProof}, orange for the shipping
  code, violet for the tests, green for Metalean; gold for the final theorem. Within a family the
  shape tells the kinds apart.
\item \lead{Status} The border of a graph node gives its status; a planned node also carries a
  second badge after its heading.
\end{itemize}

\begin{itemize}
\item \lead{Graphs} The web version lays out three kinds of dependency graph when it is built:

    uses.

  field above the graph finds a node by any of its Lean names. The link \emph{graph} in the
