## Identity

Full bibliographic entry: *MetaRocq* project website, https://metarocq.github.io/ (GitHub org `MetaRocq`, repo `github.com/MetaRocq/metarocq`, formerly `MetaCoq`/`metacoq`). This is not a paper but a live software artifact's documentation hub: a landing page plus a generated coqdoc HTML index (https://metarocq.github.io/html/toc.html) and per-package `README.md` files checked into the repo (`template/theories/README.md`, `pcuic/theories/README.md`, `safechecker/theories/README.md`, `erasure/theories/README.md`, `quotation/theories/README.md`). ACM erasure paper `metacoq-erasure-jacm`, Sozeau's habilitation `sozeau-habilitation`) -- i.e. it documents the *current* state of the repo, not a fixed published snapshot, and can drift ahead of or diverge from what any one paper describes. No version number is given anywhere on the site; content reflects whatever commit the `-` (default branch) pointer in GitHub links resolves to at fetch time.

## One-paragraph summary

The site frames MetaRocq as "a project formalizing Rocq [Coq] in Rocq and providing tools for manipulating Rocq terms and developing certified plugins," roughly 300kLoC of Rocq plus 30kLoC of extracted OCaml. It structures the project into six packages -- Template-Rocq (quoting/reification), PCUIC (the core typed calculus and its metatheory: confluence, subject reduction, validity, principality, normalization-modulo-axiom, consistency), SafeChecker (a fuel-free, extraction-ready, "correct and complete" type checker for PCUIC), Erasure (the certified erasure pipeline from PCUIC to the untyped target calculus λ□/EAst, with a battery of post-erasure optimizing transformations proved semantics-preserving), Quotation (□T -> □□T reflection), and Translations/Examples (parametricity and functional-extensionality-negation plugins, demo plugins). For Peregrine's purposes the erasure package's `README.md` is the load-bearing artifact: it names and one-line-describes every `.v` file in `erasure/theories/`, giving the authoritative module map for EAst, EWcbvEval, Extract, ErasureFunction, ErasureCorrectness, and the named post-erasure transformations (constructors-as-blocks, remove-params, inline-projections, optimize-prop-discr, plus several the CLAUDE.md list did not name: EBeta, ECoInductiveToInductive, EImplementBox, EInlining, EReorderCstrs, EUnboxing).

## What it establishes

- The project is organized as six layered packages, Template-Rocq being the shared foundation -> landing page, "Project Structure & Layers" section.
- PCUIC's metatheory includes confluence, subject reduction, validity, principality, and normalization (the last gated behind an explicit axiom) -> `pcuic/theories/README.md`, files `PCUICConfluence.v`, `PCUICSR.v`, `PCUICValidity.v`, `PCUICPrincipality.v`, `PCUICSN.v`.
- SafeChecker is claimed "correct and complete" as a fuel-free type checker for PCUIC, built from `PCUICSafeReduce` (weak-head reduction), `PCUICSafeConversion` (conversion checker), `PCUICSafeRetyping` (fast inference assuming well-typedness), `PCUICSafeChecker` (type inference/checking) -> `safechecker/theories/README.md`.
- Erasure is described as "a verified procedure to [translate PCUIC to] untyped lambda-calculus with optimization passes," with `Extract.v` holding "the erasure relation," `ErasureCorrectness.v` its correctness proof, and `ErasureFunction.v` "the erasure function defined on well-typed terms and its correctness proof" -> `erasure/theories/README.md`.
- Each of the four named post-erasure transformations is its own file with a one-line stated purpose: `EInlineProjections` ("inlines projections to cases"), `EOptimizePropDiscr` ("removing cases on propositional content"), `EConstructorsAsBlocks` ("transform constructor applications into an atomic construct"), `ERemoveParams` ("remove constructor parameters") -> `erasure/theories/README.md`.
- `ETransform.v` is named as the file giving "definitions of transformations from PCUIC to λ-box," i.e. the pipeline-composition/`Transform` machinery; `Erasure.v` is named as "the complete erasure pipeline" -> `erasure/theories/README.md`.
- The full coqdoc module list for `erasure/` (from the generated toc) additionally names files the README prose does not single out: `EBeta`, `ECoInductiveToInductive`, `EGlobalFragment`, `EImplementBox`, `EInlining`, `EPrimitive`, `EReorderCstrs`, `EUnboxing`, `EWcbvEvalCstrsAsBlocksFixLambdaInd`, `EWcbvEvalCstrsAsBlocksInd`, `EWcbvEvalEtaInd`, `EWcbvEvalNamed`, `EWtAst`, `ErasureFunctionProperties`, `ErasureProperties` -> https://metarocq.github.io/html/toc.html.

## Position in the pipeline

- [kernel theory]: PCUIC's typing and conversion (declarative + algorithmic cumulativity) are defined and its metatheory (confluence, SR, validity, principality) proved -- `pcuic/theories/README.md`.
- [kernel verification (type checker correctness)]: SafeChecker package, claimed correct-and-complete fuel-free checker for PCUIC -- `safechecker/theories/README.md`.
- [erasure theory]: `Extract.v`'s erasure relation plus `EWellformed`/`EProgram`/`EEtaExpanded(Fix)` invariants -- `erasure/theories/README.md`.
- [erasure verification]: `ErasureCorrectness.v` (relation correctness) and `ErasureFunction.v`/`ErasureFunctionProperties.v` (function correctness against the relation) -- same README.
- [erasure implementation]: `ErasureFunction.v` is the actual algorithm (not just spec); `Loader.v`/`Extraction.v` wire it into the OCaml plugin -- same README.
- [post-erasure pipeline]: `EConstructorsAsBlocks`, `ERemoveParams`, `EInlineProjections`, `EOptimizePropDiscr`, `EInlining`, `EUnboxing`, `EBeta`, `EImplementBox`, `EReorderCstrs`, `ECoInductiveToInductive`, composed via `ETransform.v`/`Erasure.v` -- same README, plus coqdoc toc for the extra file names.
- [extraction implementation]: Not separately documented on this site beyond the erasure plugin itself; Template-Rocq's `TemplateMonad`/quoting layer is the reification side, documented in `template/theories/README.md`, but that is source-side reflection, not target-side code generation (Peregrine's backends are downstream of this whole repo, not part of it).

## Terminology map

- **λ-box / λ□**: this site's and MetaRocq's own name for the untyped target calculus; equals Peregrine's "λ□"/"lambda-box" and Letouzey's original "box" placeholder for erased proof content.
- **EAst**: MetaRocq's Rocq inductive type for λ□ syntax; Peregrine's `.ast` S-expression format serializes exactly this type (per CLAUDE.md, "node names mirror MetaCoq constructors exactly").
- **ExAst**: not on this site's page content directly, but referenced by CLAUDE.md as ConCert's *typed* variant (λ□ᵀ); the erasure README's untyped `EAst` is the base type ExAst extends for the Rust/Elm typed pipeline.
- **the erasure relation (`Extract`)**: MetaRocq's term for what CLAUDE.md and other sources may call "erasure" as a relation vs. "isErasable"/"is_erasable" as the *decision procedure* for which subterms erase to `tBox` -- this site does not use the term "isErasable" explicitly in the fetched pages, but `ErasureFunction.v` is where that decision procedure would live (it is not separately named in the README's one-line list, suggesting it is internal to `ErasureFunction.v` rather than its own file).
- **EWcbvEval**: this site's name for what other sources (e.g. the Lean-side re-formalization per the user's memory notes) call "WcbvEval" -- MetaRocq's memory note "λ□ WcbvEval semantics" explicitly says the Lean-side target semantics were "unified into faithful WcbvEval (EWcbvEval translation)," i.e. `EWcbvEval` is the canonical name this site documents and the Lean project's own semantics is a translation of it.
- **block vs applied constructor form**: this site's `EConstructorsAsBlocks.v` ("transform constructor applications into an atomic construct") is the formal home of the "block vs applied form" distinction CLAUDE.md calls out as a recurring cross-repo bug source (agda2lambox eta-expands to blocks; Lean emits applied form); `EEtaExpanded.v`/`EEtaExpandedFix.v` are the associated well-formedness predicates.
- **Transform / pipeline**: `ETransform.v`'s `Transform` abstraction is MetaRocq's name for what Peregrine's own middle-end (per CLAUDE.md, "λ□ transforms," "pipeline config," `peregrine-tool/theories/erasure/Transforms.v`) reimplements and extends on the OCaml/Rocq extraction side -- Peregrine's `Transforms.v` is a *consumer/reimplementation* of the same conceptual layer this site's `ETransform.v` documents upstream, not the same file.
